Cos'è UDebate
UDebate è una piattaforma web che digitalizza il mondo del debate universitario. Gli studenti accedono, creano un argomento, gli altri lo commentano e votano — il tutto in tempo reale, con un sistema di moderazione basato sull'intelligenza artificiale.

Dal punto di vista tecnico, il progetto si basa su Laravel, il framework PHP più diffuso al mondo, arricchito da Livewire per la reattività del frontend, e containerizzato con Docker per garantire un deploy ripetibile su qualsiasi macchina.
01 — Panoramica

Cos'è UDebate e cosa fa

Una piattaforma dove ogni utente può aprire un debate, ricevere commenti e voti dagli altri — il tutto moderato da un'AI.

~2 min
Tre aree principali
UDebate risponde a una domanda semplice: come si porta online la cultura del dibattito accademico? Il risultato è una web app articolata in tre aree principali:

1. La Home pubblica — accessibile a tutti, mostra la piattaforma e invita a registrarsi.
2. La Dashboard utente — il cuore del sito: qui si creano e si leggono i debate, si vota e si commenta.
3. Il Pannello moderatore — solo per gli account con ruolo moderator: gestisce il "topic del giorno" e monitora la piattaforma.

Un elemento particolarmente rilevante è l'integrazione con Groq AI: ogni testo pubblicato viene analizzato automaticamente da un LLM prima di essere salvato. Se contiene linguaggio offensivo, viene bloccato con un messaggio di errore.

Laravel e il pattern MVC

Laravel è il framework PHP che struttura tutta la logica dell'applicazione secondo il pattern Model-View-Controller.

~3 min
Struttura e flusso delle richieste
Laravel è il framework PHP più usato al mondo. Ogni richiesta HTTP parte dalle Routes, viene gestita da un Controller, che usa i Model per leggere o scrivere nel database, e infine restituisce una View Blade all'utente.

app/Http/Controllers/DebateController.php Apri su GitHub 
<?php

namespace App\Http\Controllers;

use App\Models\Debate;
use Illuminate\Http\Request;
use App\Models\Like;
use App\Models\Comment;
use App\Services\GroqModerationService; 
use App\Models\DailyTopic;

class DebateController extends Controller
{
    protected $moderator;

    public function __construct(GroqModerationService $moderator)
    {
        $this->moderator = $moderator;
    }

    public function index(Request $request)
    {
        $search = $request->input('q');
        $user = auth()->user();
        $dailyTopic = DailyTopic::latest()->first();

        $debates = Debate::with(['user', 'likes', 'comments.user'])
            ->when($search, function ($query, $search) {
                $query->where('title', 'like', '%' . $search . '%')
                      ->orWhere('message', 'like', '%' . $search . '%');
            })
            ->latest()
            ->get();

        $debatesCount     = $user->debates()->count();
        $votesReceived    = Like::whereIn('debate_id', $user->debates()->pluck('id'))->count();
        $commentsReceived = Comment::whereIn('debate_id', $user->debates()->pluck('id'))->count();

        $myDebates        = $user->debates()->latest()->take(5)->get();
        $likesReceived    = Like::whereIn('debate_id', $user->debates()->pluck('id'))->with('debate')->latest()->take(5)->get();
        $commentsOnMine   = Comment::whereIn('debate_id', $user->debates()->pluck('id'))->with(['user', 'debate'])->latest()->take(5)->get();

        return view('dashboard', compact(
            'debates', 'debatesCount', 'votesReceived', 'commentsReceived', 
            'myDebates', 'likesReceived', 'commentsOnMine', 'dailyTopic'
        ));
    }

    public function store(Request $request)
    {
        $validated = $request->validate([
            'title' => 'required|string|max:255',
            'message' => 'required|string',
        ]);

        $textToAnalyze = $validated['title'] . " " . $validated['message'];

        if ($this->moderator->isOffensive($textToAnalyze)) {
            return back()->withErrors(['message' => 'Linguaggio inappropriato rilevato. Rivedi il testo.'])->withInput(); 
        }

        $request->user()->debates()->create($validated);

        return redirect()->route('dashboard')->with('success', 'Dibattito pubblicato!');
    }

    public function update(Request $request, Debate $debate)
    {
        if ($debate->user_id !== auth()->id()) abort(403);
        $validated = $request->validate([
            'title' => 'required|string|max:255',
            'message' => 'required|string|max:1000',
        ]);
        $textToAnalyze = $validated['title'] . " " . $validated['message'];

        if ($this->moderator->isOffensive($textToAnalyze)) {
            return back()->withErrors(['message' => 'Linguaggio inappropriato rilevato. Rivedi il testo.'])->withInput();
        }

        $debate->update($validated);
        return back()->with('success', 'Dibattito aggiornato!');
    }

    public function destroy(Debate $debate)
    {
        if ($debate->user_id !== auth()->id()) abort(403);
        $debate->delete();
        return back()->with('success', 'Dibattito eliminato.');
    }
}
💡 Eager Loading con with()
Debate::with(['user','likes','comments.user']) è l'eager loading di Eloquent: carica in una sola query SQL tutte le relazioni necessarie, evitando il classico problema N+1 (senza questo, ci sarebbero decine di query separate per ogni debate nella lista).
03 — Livewire & Volt

Frontend reattivo senza JavaScript

Livewire permette di creare interfacce dinamiche usando solo PHP e Blade, con comunicazione AJAX automatica al server.

~2 min
Come funziona Livewire
Normalmente, per avere un'interfaccia reattiva — cioè che si aggiorna senza ricaricare la pagina — occorre scrivere JavaScript o usare framework come React o Vue.

Con Livewire, tutto questo si fa in PHP. Ogni componente ha delle proprietà PHP e dei metodi PHP; quando l'utente interagisce col browser, Livewire fa una chiamata AJAX automatica al server, esegue il metodo PHP, e aggiorna solo la parte di HTML che è cambiata.

Nel progetto viene usato per il form di login, il profilo utente e la navigazione dell'app.

    public string $email = '';
    public string $password = '';
    public bool $remember = false;

    public function authenticate(): void
    {
        // Validazione lato server automatica
        $this->validate([
            'email'    => ['required', 'string', 'email'],
            'password' => ['required', 'string'],
        ]);

        // Tentativo di login con throttle anti-brute-force
        if (! Auth::attempt(...)) {
            throw ValidationException::withMessages([
                'email' => trans('auth.failed'),
            ]);
        }
        Session::regenerate();
    }
}
app/Livewire/Forms/LoginForm.php Apri su GitHub 
<?php

namespace App\Livewire\Forms;

use Illuminate\Auth\Events\Lockout;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\Str;
use Illuminate\Validation\ValidationException;
use Livewire\Attributes\Validate;
use Livewire\Form;

class LoginForm extends Form
{
    #[Validate('required|string|email')]
    public string $email = '';

    #[Validate('required|string')]
    public string $password = '';

    #[Validate('boolean')]
    public bool $remember = false;

    public function authenticate(): void
    {
        $this->ensureIsNotRateLimited();

        if (! Auth::attempt($this->only(['email', 'password']), $this->remember)) {
            RateLimiter::hit($this->throttleKey());

            throw ValidationException::withMessages([
                'form.email' => trans('auth.failed'),
            ]);
        }

        RateLimiter::clear($this->throttleKey());
    }

    protected function ensureIsNotRateLimited(): void
    {
        if (! RateLimiter::tooManyAttempts($this->throttleKey(), 5)) {
            return;
        }

        event(new Lockout(request()));

        $seconds = RateLimiter::availableIn($this->throttleKey());

        throw ValidationException::withMessages([
            'form.email' => trans('auth.throttle', [
                'seconds' => $seconds,
                'minutes' => ceil($seconds / 60),
            ]),
        ]);
    }

    protected function throttleKey(): string
    {
        return Str::transliterate(Str::lower($this->email).'|'.request()->ip());
    }
}
⚡ Come funziona wire:model
Nel template Blade il campo email è semplicemente:
<input wire:model="email" />

Ogni volta che l'utente digita, Livewire aggiorna automaticamente la proprietà PHP $email senza scrivere una riga di JavaScript.

Il metodo authenticate() viene chiamato al submit, direttamente sul server, con validazione e gestione errori inclusa.
04 — Autenticazione

Login, Registrazione e Ruoli

Laravel Breeze fornisce lo scaffolding completo per auth. Il sistema di ruoli è stato aggiunto con un middleware custom.

~2 min
Sistema di autenticazione e ruoli
L'autenticazione è gestita da Laravel Breeze, che fornisce le pagine di login, registrazione, reset password e verifica email già funzionanti. Sopra di esso è stato costruito un sistema di ruoli: ogni utente ha un campo role nel database, con valore di default 'user'. I moderatori hanno role = 'moderator'.

Per proteggere le rotte admin è stato scritto un Middleware custom chiamato EnsureModerator: intercetta ogni richiesta verso /moderator/* e verifica il ruolo. Se l'utente non è un moderatore, riceve un errore 403.
app/Http/Middleware/EnsureModerator.phpApri su GitHub 
class EnsureModerator
{
    public function handle(
        Request $request,
        Closure $next
    ) {
        // Blocca ospiti o utenti senza ruolo moderatore
        if (! auth()->check()
            || ! auth()->user()->isModerator()) {

            abort(403, 'Accesso riservato ai moderatori.');
        }

        // Utente autorizzato: procede
        return $next($request);
    }
}

05 — Gestione Debate

Crea, vota, commenta

Il flusso completo: dalla creazione di un debate, ai like con risposta JSON, ai commenti salvati in tempo reale.

~3 min
Il flusso di creazione e interazione
Quando un utente crea un debate, compila titolo e messaggio nel form e invia una POST a /debates, che arriva al metodo store() del DebateController.

Qui avvengono tre operazioni in sequenza: prima la validazione Laravel dei campi, poi il controllo AI di Groq, e infine il salvataggio nel database tramite Eloquent con create().

Per i like viene usata la pattern del "toggle": se l'utente ha già messo like, viene rimosso — altrimenti viene aggiunto. La risposta è JSON, così il frontend aggiorna il contatore senza ricaricare la pagina.
app/Http/Controllers/DebateController.php — store()Apri su GitHub 
public function store(Request $request)
{
    // 1. Validazione Laravel: campi required, tipo e lunghezza
    $validated = $request->validate([
        'title'   => 'required|string|max:255',
        'message' => 'required|string',
    ]);

    // 2. Analisi AI anti-insulti (Groq LLaMA 3.1)
    $textToAnalyze = $validated['title'] . ' ' . $validated['message'];

    if ($this->moderator->isOffensive($textToAnalyze)) {
        return back()
            ->withErrors(['message' => 'Linguaggio inappropriato rilevato.'])
            ->withInput(); // mantiene i valori nel form
    }

    // 3. Salvataggio: relazione user -> debates
    $request->user()->debates()->create($validated);

    return redirect()->route('dashboard')
                    ->with('success', 'Dibattito pubblicato!');
}

public function toggle(Debate $debate)
{
    $user     = auth()->user();
    $hasLiked = $debate->isLikedBy($user);

    if ($hasLiked) {
        $debate->likes()->where('user_id', $user->id)->delete();
        $isNowLiked = false;
    } else {
        $debate->likes()->create(['user_id' => $user->id]);
        $isNowLiked = true;
    }

    // Risposta JSON per aggiornamento frontend senza reload
    if (request()->wantsJson()) {
        return response()->json([
            'liked' => $isNowLiked,
            'count' => $debate->likes()->count()
        ]);
    }
    return back();
}

06 — Moderazione AI

Groq + LLaMA 3.1 — anti-insulti

Ogni testo pubblicato viene analizzato da un LLM prima di essere salvato. È la funzionalità più originale del progetto.

~2 min
Integrazione AI nel backend PHP
Il progetto integra Groq, un servizio di AI inference ad alta velocità, che usa il modello LLaMA 3.1 8B Instant.

Prima di salvare qualsiasi testo nel database, il GroqModerationService esegue una chiamata HTTP all'API di Groq passando il testo da analizzare. Il modello riceve un system prompt in italiano che gli chiede di rispondere solo "true" se il testo è offensivo, o "false" altrimenti.

Temperature a 0 e max_tokens a 5: questo rende la risposta deterministica e velocissima (una sola parola). Latenza ~200ms, costo quasi nullo.
app/Services/GroqModerationService.phpApri su GitHub 
public function isOffensive(string $text): bool
{
    $apiKey = env('GROQ_API_KEY');

    // Chiamata HTTP a Groq con LLaMA 3.1 8B
    $response = Http::withToken($apiKey)
        ->post('https://api.groq.com/openai/v1/chat/completions', [
            'model'       => 'llama-3.1-8b-instant',
            'messages'    => [
                [
                    'role'    => 'system',
                    'content' => 'Sei un moderatore severo. Il testo
è in ITALIANO. Se contiene insulti, parolacce, odio o
volgarità, rispondi SOLO con la parola "true".
Altrimenti rispondi SOLO con la parola "false".'
                ],
                ['role' => 'user', 'content' => $text]
            ],
            'temperature' => 0,     // risposta deterministica
            'max_tokens'  => 5      // basta una parola
        ]);

    if ($response->successful()) {
        $result = trim(strtolower(
            $response->json('choices.0.message.content')
        ));
        return str_contains($result, 'true');
    }
    return false; // in caso di errore API: lascia passare
}
app/Services/GroqModerationService.php Apri su GitHub 
<?php
namespace App\Services;
use Illuminate\Support\Facades\Http;
use Illuminate\Support\Facades\Log;

class GroqModerationService
{
    public function isOffensive(string $text): bool
    {
        $apiKey = env('GROQ_API_KEY');

        if (empty($apiKey)) {
            Log::error('Groq API Key mancante nel file .env');
            return false; 
        }

        $response = Http::withToken($apiKey)
            ->post('https://api.groq.com/openai/v1/chat/completions', [
                'model' => 'llama-3.1-8b-instant',
                'messages' => [
                    [
                        'role' => 'system',
                        'content' => 'Sei un moderatore severo. Il testo dell\'utente è in ITALIANO. Se il testo contiene insulti, parolacce, odio o volgarità, rispondi ESATTAMENTE E SOLO con la parola "true". Se il testo è pulito e normale, rispondi ESATTAMENTE E SOLO con la parola "false". Non aggiungere nessuna punteggiatura o altra parola.'
                    ],
                    [
                        'role' => 'user',
                        'content' => $text
                    ]
                ],
                'temperature' => 0,
                'max_tokens' => 5 
            ]);

        if ($response->successful()) {
            $result = trim(strtolower($response->json('choices.0.message.content')));
            return str_contains($result, 'true');
        }

        Log::error('Errore chiamata Groq API: ' . $response->body());        
        return false;
    }
}
🤖 Perché questa scelta tecnica funziona
Temperature 0 = nessuna creatività, risposta sempre uguale per lo stesso input. Max tokens 5 = il modello non può scrivere più di una parola, risparmiando token e riducendo la latenza a ~200ms. Il system prompt in italiano è cruciale: i modelli capiscono meglio le istruzioni nella stessa lingua del testo da analizzare.
07 — Pannello Moderatore

Gestione della piattaforma

Il moderatore ha un pannello dedicato per monitorare la piattaforma e impostare il topic del giorno.

~1 min
Il pannello di controllo
Il pannello moderatore è accessibile solo agli account con ruolo moderator. Da qui si visualizza il totale degli utenti iscritti e dei debate pubblicati, e si può impostare il topic del giorno: una domanda o un tema che viene mostrato a tutti gli utenti nella dashboard come spunto per aprire nuovi debate.

Anche questo input passa attraverso la moderazione AI prima di essere salvato. Viene usato updateOrCreate() di Eloquent: se esiste già un topic con id=1, lo aggiorna; altrimenti lo crea. C'è sempre e solo un topic del giorno attivo.

public function updateTopic(Request $request)
{
    $request->validate([
        'topic' => 'required|string|max:255'
    ]);

    // Check AI prima del salvataggio
    if ($this->moderator->isOffensive($request->topic)) {
        return back()->withErrors([
            'topic' => 'Il topic inserito è inappropriato.'
        ]);
    }

    // updateOrCreate: aggiorna se id=1 esiste, crea altrimenti
    DailyTopic::updateOrCreate(
        ['id' => 1],
        ['topic' => $request->topic]
    );

    return back()->with('success', 'Topic aggiornato!');
}

<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use App\Models\User;
use App\Models\Debate;
use App\Models\DailyTopic;
use App\Services\GroqModerationService;

class ModeratorController extends Controller
{
    protected $moderator;
    
    public function __construct(GroqModerationService $moderator)
    {
        $this->moderator = $moderator;
    }

    public function index()
    {
        $usersCount = User::count();
        $debatesCount = Debate::count();
        $currentTopic = DailyTopic::latest()->first();

        return view('moderator.dashboard', compact('usersCount', 'debatesCount', 'currentTopic'));
    }

    public function updateTopic(Request $request)
    {
        $request->validate([
            'topic' => 'required|string|max:255'
        ]);

        if ($this->moderator->isOffensive($request->topic)) {
            return back()->withErrors(['topic' => 'Il topic inserito è inappropriato.']);
        }

        DailyTopic::updateOrCreate(
            ['id' => 1], 
            ['topic' => $request->topic]
        );

        return back()->with('success', 'Topic del giorno aggiornato correttamente!');
    }
}
08 — Database

Schema relazionale & Migrations

Il database è versionato tramite Migrations Laravel. Ogni tabella è una classe PHP — mai più SQL scritto a mano.

Migrations e schema relazionale
In Laravel, lo schema del database non viene creato manualmente con SQL: si usano le Migrations, file PHP che descrivono ogni modifica al DB. Il comando php artisan migrate le esegue in ordine. Questo permette di ricreare l'intero database su qualsiasi macchina — incluso il container Docker — con un solo comando.

🔑 Unique constraint sui Like
La tabella likes ha un vincolo UNIQUE su (user_id, debate_id): questo impedisce a livello di database che lo stesso utente metta like due volte allo stesso debate, anche in presenza di bug nel codice PHP. La sicurezza è duplice: nel Controller e nel DB.
09 — Deploy

Docker Compose — tre container, un comando

L'intera infrastruttura è containerizzata: l'app Laravel, il database MySQL e phpMyAdmin si avviano insieme.

~1 min
Infrastruttura containerizzata
Con Docker Compose l'intero progetto è avviabile su qualsiasi macchina. Un unico file docker-compose.yml definisce tre servizi:

app — l'applicazione Laravel con PHP 8.3, costruita dal Dockerfile.
db — MySQL 8.0 con volume persistente, così i dati non si perdono al riavvio.
phpmyadmin — interfaccia web per ispezionare il database durante lo sviluppo.

Per avviare tutto: docker compose up --build
docker-compose.yml (struttura semplificata)Apri su GitHub 
services:

  app:
    build: .               # usa il Dockerfile nella root
    ports:
      - "8080:80"         # localhost:8080 → Apache nel container
    depends_on:
      db:
        condition: service_healthy

  db:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE:  udebate
      MYSQL_ROOT_PASSWORD: secret
    ports:
      - "3307:3306"       # porta 3307 per evitare conflitti locali
    volumes:
      - db_data:/var/lib/mysql  # dati persistenti
    healthcheck:          # attende MySQL prima di avviare app
      test: ["CMD", "mysqladmin", "ping"]

  phpmyadmin:
    image: phpmyadmin:5
    ports:
      - "8081:80"         # interfaccia web su localhost:8081
    environment:
      PMA_HOST: db        # si connette al service "db"

volumes:
  db_data:               # volume named persistente
10 — Conclusioni

Riepilogo & Punti di forza

Cosa abbiamo realizzato, cosa funziona bene, e cosa potrebbe essere esteso in futuro.

~1 min
Sintesi del progetto
UDebate integra diverse tecnologie moderne in modo coerente. Laravel ha fornito la struttura, Livewire ha eliminato la necessità di scrivere JavaScript, Docker ha reso il deploy riproducibile, e Groq ha aggiunto una dimensione di intelligenza artificiale applicata a un problema reale — la moderazione dei contenuti.

I tre elementi tecnici più significativi del progetto sono:
1. L'Eager Loading con Eloquent, che ottimizza le query SQL ed evita il problema N+1.
2. Il Middleware custom EnsureModerator, che mostra come si estende il ciclo di vita delle richieste in Laravel.
3. La GroqModerationService, che dimostra come integrare un LLM nel backend PHP con latenza e costo minimi.
🏗️
Architettura MVC
Separazione netta logica/dati/presentazione. Codice leggibile e manutenibile.
⚡
Zero JavaScript manuale
Livewire gestisce tutta la reattività lato server. Il team ha potuto concentrarsi sul PHP.
🤖
AI applicata
Groq + LLaMA 3.1 per moderazione automatica. Latenza ~200ms, costo quasi zero.
🐳
Deploy riproducibile
docker compose up --build avvia tutto in un comando. Nessun "funziona sul mio PC".
🔒
Sicurezza a strati
CSRF protection, password hashed, UNIQUE constraint DB, middleware di autorizzazione.
📈
Scalabilità futura
Struttura pronta per: notifiche real-time, sistema di tag, ranking debate, API REST.
